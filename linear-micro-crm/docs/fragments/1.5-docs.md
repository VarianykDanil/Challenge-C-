## In one paragraph

The documents now say what is true. Linear Hub was built by one developer at Noryn System Ltd directing AI coding
agents, with automated tests and independent reviews; the five people the old pages named never existed. The pitch
describes the real offer (a licensed system with a monthly service, the outside services it can connect to, HTTPS on a
small server, 14-hour sessions). The 1.3 owner notes lose the notes between work packages. A proprietary LICENSE says
Noryn System Ltd owns Linear Hub and licenses it to Linear MCR Limited. And there is now a real, tested path online:
`deploy/install.sh` sets up a small Ubuntu 24.04 server with Caddy and HTTPS, a firewall, automatic security updates,
encrypted off-site copies and a health check, and `docs/DEPLOY.md` is the go-live runbook around it. The roadmap no
longer offers Supabase as the next step: SQLite stays, and a different database is a later option with its honest
reason and size. `docs/MAINTAINERS.md` lets another developer take Linear Hub over. The pitch and the runbook say
plainly that going online is outside the signed agreement: a fixed-price go-live package and a signed variation
(clauses 9.3 and 26.2) come first.

## The installer, for developers and Noryn

`sudo bash deploy/install.sh` on a fresh Ubuntu 24.04 LTS server (amd64 or arm64). It asks for the domain, an email for
certificate notices, the repository and the release, where off-site copies go, an optional heartbeat address and
whether to turn off SSH password log-in; `--help` lists the options (`--domain`, `--email`, `--repo`, `--ref`,
`--port`, `--offsite storagebox|s3|existing|none`, `--storagebox-host`, `--storagebox-user`, `--s3-endpoint`,
`--s3-bucket`, `--s3-region`, `--s3-access-key-id` with `S3_SECRET_ACCESS_KEY` in the environment, `--offsite-path`,
`--heartbeat-url`, `--ssh-keys-only`, `--yes`, `--dry-run`, `--preview`, `--allow-no-systemd` for containers).

What it does, every step safe to run again: system packages; a 2 GB swap file under 2 GB of memory; automatic security
updates (Ubuntu and Caddy, restart at about 04:30 when needed; Node is left to Noryn); ufw with SSH (rate-limited),
80 and 443 only; optional SSH keys-only; Node.js 22 LTS from NodeSource (22.18+; 24 and 26 accepted); a `linear`
system user with no shell; the code cloned as that user (a private repository gets a read-only deploy key) and
`npm run setup`; a new 64-hex app key in `/etc/linear-hub/keys/app-secret` only when there is no database yet; a new
off-site passphrase (six groups of five, shown once, typed back, never logged) in
`/etc/linear-hub/keys/backup-passphrase`; the settings file `/etc/linear-hub/linear-hub.env` (0600 root) with
`TZ=Europe/London`, `NODE_NO_WARNINGS=1`, `HOST=127.0.0.1`, `PORT` (4000), `DB_PATH=/var/lib/linear-hub/linear.sqlite`,
`LM_BACKUP_DIR`, `LM_STATEMENTS_DIR`, `LM_UPLOADS_DIR` (all under `/var/lib/linear-hub`),
`LM_APP_SECRET_FILE=/etc/linear-hub/keys/app-secret`, `LM_OFFSITE_DIR=/var/lib/linear-hub/offsite`,
`LM_BACKUP_PASSPHRASE_FILE=/etc/linear-hub/keys/backup-passphrase`, `TRUST_PROXY=1`, `COOKIE_SECURE=1`,
`LM_DEMO_ACCOUNTS=0` (other lines the owner adds are kept; `LM_PAYMENTS_FAKE`, `LM_BUSINESS_NOW`, `LM_TLS_CERT_FILE`,
`LM_TLS_KEY_FILE` and `NODE_ENV` are removed with a message; `LM_APP_SECRET` is kept with a warning); a locked-down
systemd unit (`ProtectSystem=strict`, writes only `/var/lib/linear-hub`, no new privileges, no capabilities, a system
call filter, `RestartPreventExitStatus=78` so a wrong key does not loop); Caddy with automatic HTTPS (the Caddyfile is
checked with `caddy validate` as the `caddy` user before use, and put back if refused; a Caddy log that is not caddy's
is given back on every run); the off-site store (a Storage Box's host keys recorded and their fingerprints shown, the
remote made afresh whenever an answer changes, the S3 region worked out or asked, the store proven by writing a check
file); the nightly off-site copy (rclone `copy`, never `sync`, at 03:15 London, `--size-only` so a copy cut off half-way
is sent again, videos still uploading skipped; the learning videos through an rclone crypt remote locked with the same
passphrase; a status file and a heartbeat ping after a good copy; its own locked-down unit that may write only the data
folder and rclone's settings); and `/usr/local/bin/linear-hub`. Every run that has no heartbeat address ends with a
warning.

`sudo linear-hub help`: `status`, `logs [-f]`, `start`, `stop`, `restart`, `update [TAG]` (backs up and checks first,
prints the way back),
`import FILE.lhbk [--passphrase-file FILE] [--yes --forget-payments]`, `golive`, `restore FILE` (a name from `backups`, or
a path; a file the `linear` user cannot read is copied in first), `restore-test` (downloads
the newest off-site copy, decrypts it with the passphrase, starts it on a scratch port with payments, Gmail and backups
off, counts people and gauge entries, deletes it), `offsite-sync`, `key:restore`, `recovery-sheet`, `doctor`, `backup`,
`backups`, `setup-code EMAIL`, `2fa:reset EMAIL`, `pin:reset EMAIL`. `LH_RESTORE_TEST_PORT` moves the restore test's
scratch port (default: the app port + 100).

Tests:

- `bash deploy/tests/run.sh`: no root, no network. Shellcheck (style level) on every script when installed
  (`LH_REQUIRE_SHELLCHECK=1` makes it required), the installer's helpers (answers, the settings merge, templates), a
  full `--dry-run` on a pretend fresh server checking every file it would write and every command it would run, wrong
  answers stopping before anything changes, each off-site choice, the S3 region rules, the remote matching, the Caddy
  log, and `systemd-analyze --offline security` scores for both units when systemd-analyze 250+ is installed. It also
  runs inside `npm test`
  (`server/src/test/docs-claims.test.ts`) on Linux with bash 4+, so CI checks the installer on every change.
- `bash deploy/tests/container-test.sh <repository folder> <branch>`: needs Docker. Installs from scratch in a throwaway
  Ubuntu 24.04 container and checks the result (see "Verification" below). Settings for the test machine only:
  `LH_TEST_IMAGE`, `LH_TEST_PORT`, `LH_TEST_PORT2`, `LH_TEST_PREINSTALL=1` (Node from nodejs.org with its checksum and
  Ubuntu's Caddy, for networks that block NodeSource and Cloudsmith), `LH_TEST_NODE_DIR` (copy Node from the test
  machine instead), `HTTPS_PROXY`, `LH_TEST_CA`, and `LH_TEST_SYSTEMD=1` (step 8: boot the installed machine with
  systemd in a privileged container with no network and run the real units).

No new settings for the app itself.
