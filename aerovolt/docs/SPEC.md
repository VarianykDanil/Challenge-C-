# AeroVolt — Engineering Specification (interface contract)

AeroVolt is a telemetry and analysis platform for a Formula Student **electric** race car.
It covers two systems:

* **System 1 – Aero sensing:** wing/undertray pressure taps, pitot, ambient air, ride height,
  suspension loads, IMU/GPS → Cp maps, downforce, drag, CL·A, CD·A, aero balance, L/D,
  sensor-fault vs real-aero-problem detection.
* **System 2 – EV powertrain sensing:** motor, inverter, accumulator (every cell), BMS,
  cooling loop, safety chain → SoC estimation (Coulomb counting + EKF), energy per lap,
  endurance strategy, thermal and safety alerts.

It runs in **demo mode** from a physics simulator of the car on a Formula Student track, and
connects to **real sensors** (USB-serial sensor nodes or the car's CAN bus) by changing the
config file. Sim and real sources can run together ("hybrid"): a real sensor overrides the
simulated value of the same channel. That is the Phase-2 bench demo: one real pressure sensor
drives one tap on the 3D car while everything else is simulated.

This document is the contract between modules. Every module must follow the names, units,
message formats and file locations below. If you need to deviate, document it in this file.

---------------------------------------------------------------------------------------------

## 0. Ground rules

* Python ≥ 3.10. Runtime deps (`requirements.txt`): `numpy`, `pyyaml`, `aiohttp`.
  Hardware deps (`requirements-hw.txt`): `python-can`, `cantools`, `pyserial` — **import these
  lazily** inside the CAN/serial modules so the sim-only demo works without them.
  Dev deps (`requirements-dev.txt`): `pytest` (+ hw deps for the full test suite).
  No other third-party Python packages.
* All paths below are relative to the project root `aerovolt/` (the folder containing this
  `docs/` folder). The Python package is `aerovolt/aerovolt/`. Commands are run from the
  project root: `python -m aerovolt --config config/demo.yaml`, `python -m pytest -q`.
* Units: SI unless the channel catalogue says otherwise. Temperatures in °C. Ride height and
  damper position in mm (sensor-native). Pressures in Pa. Speeds in m/s (UI may show km/h).
  Angles in degrees in channels, radians inside maths.
* Vehicle coordinate frame (ISO 8855): origin on the ground plane, on the car centreline, at the
  **front axle**. `x` forward (nose is +x, rear axle at x = −wheelbase), `y` to the driver's
  left, `z` up. Metres.
* Three.js mapping (web): `three.X = car.x`, `three.Y = car.z`, `three.Z = −car.y`.
* Time: `t` = session time in seconds (float), starts at 0 when the session starts. Sim time
  for the simulator; arrival time (monotonic) for real sources.
* Missing / invalid value: `float('nan')` in Python, `null` in JSON. Never send NaN in JSON.
* Code style: clear, well-named, type-hinted Python; docstrings explain the physics with the
  formula used. This is a student project that will be presented to judges — the code itself
  should teach. No dead code, no TODO stubs left behind.
* Every module ships with pytest tests in `tests/`.

## 2. Channel catalogue (`config/sensors.yaml`, loaded by `core/catalog.py`)

Every measurable or derived quantity is a **channel** with a unique snake_case `id`.
`ChannelDef` (frozen dataclass in `core/model.py`):

| field | type | meaning |
|---|---|---|
| id | str | unique id, e.g. `fw_p03`, `cell_v_047`, `calc_cla` |
| name | str | human label, e.g. "Front wing L tap 3 (suction, x/c 0.45)" |
| unit | str | `Pa`, `°C`, `V`, `A`, `N`, `mm`, `m/s`, `m/s²`, `deg`, `deg/s`, `rpm`, `Nm`, `%`, `kW`, `kWh`, `kg/m³`, `m²`, `L/min`, `kΩ`, `bar`, `bool`, `enum`, `-` |
| system | str | `aero` / `powertrain` / `vehicle` / `calc` / `truth` |
| group | str | see table below |
| rate_hz | float | nominal sample rate |
| min, max | float | physical range of the sensor (gauges, plausibility) |
| noise | float | 1-σ noise used by the virtual sensor (sim) |
| resolution | float | quantisation step (sim) |
| lag_s | float | first-order lag time constant (sim; e.g. pneumatic tubing) default 0 |
| warn_lo, warn_hi, crit_lo, crit_hi | float or null | display thresholds |
| derived | bool | true for `calc_*` channels (computed by analysis, never by sources) |
| meta | dict | extra info, e.g. tap geometry (below) |

The YAML supports a `repeat` construct so the 140 cell voltages / 60 cell temperatures are
not written out by hand (`id: "cell_v_{i:03d}"`, `count: 140`, `start: 0`).
`Catalog` API: `catalog[id] -> ChannelDef`, `catalog.ids(system=None, group=None)`,
`catalog.raw_ids()` (non-derived, non-truth), `catalog.taps()` (tap ChannelDefs in order),
`catalog.to_json()` (list of dicts for the web).

### 2.1 Raw channels (sources produce these)

**System 1 – aero (`system: aero`)**

| group | ids | unit | rate | notes |
|---|---|---|---|---|
| aero.taps | `fw_p01`…`fw_p12` | Pa | 50 | front wing, 2 stations × 6 taps |
| aero.taps | `rw_p01`…`rw_p12` | Pa | 50 | rear wing, 2 stations × 6 taps |
| aero.taps | `ut_p01`…`ut_p08` | Pa | 50 | undertray/diffuser |
| aero.air | `pitot_dp` | Pa | 50 | pitot total − static = dynamic pressure q |
| aero.air | `amb_temp` °C, `amb_press` Pa (absolute), `amb_rh` % | | 1 | ambient (BME280) |
| aero.air | `probe_yaw`, `probe_pitch` | deg | 50 | 5-hole probe flow angles |
| aero.ride | `rh_front`, `rh_rear` | mm | 50 | laser ride height |
| aero.loads | `fw_load`, `rw_load` | N | 50 | wing-mount load cells (vertical, +down) |

Tap pressure = local static pressure − freestream static (reference port), so `Cp = tap / q`.
Tap `meta`: `element` (`fw`/`rw`/`ut`), `station` (`L`/`R`/`C` …), `surface`
(`suction`/`pressure`/`floor`), `x_c` (chord fraction 0…1; for undertray the fraction of floor
length), `pos` `[x, y, z]` metres in car frame.

Wing tap layout — per station 6 taps, ordered: suction x/c 0.05, 0.20, 0.45, 0.75; pressure
x/c 0.10, 0.50. Inverted wings: the **suction surface is the lower surface**.
* Front wing: station L = `fw_p01–06` (y = +0.55 m), station R = `fw_p07–12` (y = −0.55 m).
* Rear wing: station L = `rw_p01–06` (y = +0.25 m), station R = `rw_p07–12` (y = −0.25 m).
* Undertray: `ut_p01–06` on the centreline at floor fractions 0.05, 0.20, 0.40 (throat), 0.60,
  0.80, 0.97 (diffuser exit); `ut_p07` left diffuser tunnel and `ut_p08` right diffuser tunnel
  at fraction 0.80, y = ±0.30 m.

**Vehicle dynamics (`system: vehicle`)**

| group | ids | unit | rate |
|---|---|---|---|
| susp | `damper_fl`, `damper_fr`, `damper_rl`, `damper_rr` (compression, + = bump) | mm | 100 |
| susp | `pushrod_fl`, `pushrod_fr`, `pushrod_rl`, `pushrod_rr` (compression force) | N | 100 |
| imu | `ax`, `ay`, `az` (az ≈ +9.81 at rest) | m/s² | 100 |
| imu | `gx`, `gy`, `gz` (roll, pitch, yaw rate) | deg/s | 100 |
| gps | `gps_lat`, `gps_lon` (deg), `gps_speed` (m/s), `gps_heading` (deg, 0 = north, clockwise) | | 10 |
| wheels | `ws_fl`, `ws_fr`, `ws_rl`, `ws_rr` | m/s | 50 |
| driver | `steer` (deg), `apps1`, `apps2` (%), `brake_press_f`, `brake_press_r` (bar) | | 50 |

**System 2 – powertrain (`system: powertrain`)**

| group | ids | unit | rate |
|---|---|---|---|
| motor | `mot_speed` rpm, `mot_torque` Nm, `mot_winding_temp` °C | | 100 / 100 / 10 |
| inverter | `inv_dc_voltage` V, `inv_dc_current` A (+ = from pack), `inv_phase_current` A rms, `inv_igbt_temp` °C, `inv_state` enum, `inv_fault` enum | | 100…10 |
| bms.pack | `pack_voltage` V, `pack_current` A (+ = discharge), `bms_soc` %, `bms_state` enum, `bms_fault` enum | | 100 / 100 / 10 |
| bms.cell_v | `cell_v_000`…`cell_v_139` | V | 10 |
| bms.cell_t | `cell_t_00`…`cell_t_59` | °C | 2 |
| cooling | `cool_temp_in`, `cool_temp_out` °C, `cool_flow` L/min, `pump_duty`, `fan_duty` % | | 10 |
| safety | `sdc_closed`, `imd_ok`, `ams_ok`, `bspd_ok`, `apps_plaus_ok`, `air_pos_closed`, `air_neg_closed`, `precharge_done` (bool 0/1), `tsal_state` enum (0 = LV/green, 1 = HV active/red), `imd_iso_kohm` kΩ | | 20 |

Enums: `inv_state` 0 = off, 1 = precharge, 2 = ready, 3 = driving, 4 = derating, 5 = fault.
`inv_fault` 0 = none, 1 = overtemp, 2 = overcurrent, 3 = DC undervoltage, 4 = comms.
`bms_state` 0 = idle, 1 = precharge, 2 = TS active, 3 = fault. `bms_fault` 0 = none,
1 = cell overvoltage, 2 = cell undervoltage, 3 = cell overtemp, 4 = comms.

Accumulator layout: 140 cells in series (each "cell" = 4 parallel 21700 cells), 5 segments ×
28. Cell `cell_v_k` is in segment `k // 28`. Temperature sensor `cell_t_j` (12 per segment)
sits between cells; sensor j covers cells `round(j*140/60)` … (document mapping in
`core/physics.py: temp_sensor_cells(j)`).

**Simulator truth (`system: truth`, only produced by the sim)** — used to show estimation
accuracy in demo mode: `truth_speed` m/s, `truth_downforce_f`, `truth_downforce_r`,
`truth_drag` N, `truth_cla`, `truth_cda` m², `truth_soc` %, `truth_s` m (distance along lap),
`truth_lap` (lap number), `truth_wind_speed` m/s, `truth_wind_dir` deg.

### 2.2 Derived channels (`system: calc`, computed by `analysis/processor.py`)

`calc_fw_asym` % (left vs right front-wing section Cl difference).

Powertrain: `calc_pack_power` kW, `calc_mot_power` kW (mechanical T·ω), `calc_inv_eff` %,
`calc_cell_v_min`, `calc_cell_v_max` V, `calc_cell_v_delta` mV, `calc_cell_v_min_idx`,

## 4. Core (`aerovolt/core/`)

* `model.py` — `ChannelDef`, `FaultInfo(id, title, system, description, active)`,
  `Alert(id, rule, severity, title, detail, channels, t_start, t_end, active)`,
  `LapSummary` (dataclass, `to_json()`), type alias `Emit = Callable[[float, dict[str, float]], None]`.
* `config.py` — `load_config(path) -> AppConfig` (dataclass): resolves relative paths against
  the project root, loads vehicle / catalogue / alerts / calibration. Merges CLI overrides.
* `catalog.py` — `Catalog` (see §2), with `repeat` expansion and validation (unique ids,
  derived ⇔ `calc_` prefix, truth ⇔ `truth_` prefix).
* `physics.py` — shared, pure, tested formulas used by BOTH sim and analysis:
  `moist_air_density(t_c, p_pa, rh_pct)`, `dynamic_pressure(rho, v)`,
  `airspeed_from_q(q, rho)`, `section_cl(xc_suction, cp_suction, xc_pressure, cp_pressure)`
  (piecewise-linear interpolation of each surface; at x/c = 0 both surfaces meet at Cp = 1
  (stagnation); at x/c = 1 both surfaces meet at the mean of their last measured values (Kutta);
  returns ∫₀¹ (Cp_pressure − Cp_suction) d(x/c), positive = downforce),
  `OCV` interpolation `ocv(soc, table)` and `docv_dsoc`, `CellModel` (R0 + one RC pair,
  Coulomb-counted SoC, `step(current_a, dt)` → terminal voltage),
  `temp_sensor_cells(j)`, wheel-load ↔ pushrod conversions
  `pushrod_from_wheel_load(load_n, ratio, unsprung_kg)` and inverse.
* `geo.py` — local tangent-plane conversion `xy_to_latlon(x, y, origin)`, `latlon_to_xy`,
  `heading_deg(dx, dy)` (0 = north = +y of the track plane, clockwise; the track plane uses
  x = east, y = north — this is the *track* frame, distinct from the vehicle frame).
* `store.py` — `ChannelStore`: `update(t, values)` (latest value + latest timestamp per channel),
  `latest(id)`, `latest_all()`, `age(id, now)`, `status(id, now) -> 'live'|'stale'|'missing'`
  (stale if no update for more than `max(0.5, 5 / rate_hz)` s), `snapshot(t)` appends one row of
  all channels to a numpy ring buffer (`history_s` default 300 s at `snapshot_hz` default 20 Hz),
  `history(ids, seconds) -> (t: ndarray, {id: ndarray})`, `reset()`.
* `source.py` — `class Source(ABC)`:
  ```python
  kind: str                       # 'sim' | 'serial' | 'can' | 'replay'
  def __init__(self, cfg: dict, ctx: "SessionContext"): ...
  async def run(self, emit: Emit) -> None   # runs until cancelled; emit(t, {channel: value})
  def provides(self) -> set[str] | None     # channels it owns (None = whatever it emits)
  def faults(self) -> list[FaultInfo]       # [] unless sim
  def set_fault(self, fault_id: str, active: bool) -> None  # NotImplementedError unless sim
  def info(self) -> dict                    # {kind, label, status: 'running'|'waiting'|'error', detail, stats{...}}
  ```
  `SessionContext` (dataclass): `config`, `catalog`, `vehicle` (dict), `root` (Path),
  `clock()` (session time for real sources), `track` (set by the sim source or loaded from
  config for real sources; may be None).
* `manager.py` — `SourceManager(sources, catalog, calibration)`: starts all sources as asyncio
  tasks, merges their emissions. **Priority = position in the config list; later sources win.**
  A value for channel C from source i is dropped if a higher-priority source j has emitted C in
  the last 1.0 s (so a real sensor overrides the sim, and if the real sensor stops, the sim
  value comes back after 1 s). Applies `calibration.yaml` (`value = (raw − offset) × scale`) to
  non-sim sources. Unknown channel ids are counted (`stats.unknown`) and dropped. Exposes
  `owner(channel)` → source kind (for the Sensors tab) and `mode` → `SIM` | `LIVE` | `HYBRID` |
  `REPLAY`.
* `events.py` — small sync pub/sub used by the session to fan events out to the server.

## 5. Simulator (`aerovolt/sim/`)

### 5.1 Tracks (`tracks.py`)
Track = closed (or open, for acceleration) centreline in the **track frame** (x east, y north,
metres) resampled every 0.5–1 m, with `s` (distance), `kappa` (signed curvature 1/m), heading,
and `start_line` (point + direction). Built from control points with a periodic cubic spline.
* `fs_endurance` (default): closed loop, lap length 900–1100 m, hairpins with ≥ 4.5 m
  centreline radius, straights ≤ 80 m, a slalom section (cones 7.5–12 m apart), a chicane and a
  few sweepers — a realistic Formula Student endurance/autocross layout. Must not
  self-intersect (test it).
* `skidpad`: figure-of-8, circles with 15.25 m inner diameter (driven radius ≈ 9.125 m).
* `acceleration`: 75 m straight + run-off (open track).
`Track.to_json(origin)` → `{name, length_m, closed, xy:[[x,y]...], latlon:[[lat,lon]...],
start:{x,y,heading_deg}, origin:{lat,lon}}` (downsampled to ≤ 1500 points).

### 5.2 Lap simulator (`lapsim.py`)
Quasi-steady-state point-mass solver used both by the sim and by `analysis/strategy.py`:
`solve(track, vehicle_params, power_limit_kw, aero_overrides=None) -> LapResult` with arrays
`s, v, ax, ay, t, power_kw` and scalars `lap_time, energy_kwh` (battery side, including
driveline/inverter/motor efficiency and regen). Corner speed from lateral grip with
aerodynamic load: `m v² |κ| = μ_lat (m g + ½ ρ CL·A v²)`; forward pass limited by traction
(rear-wheel drive, rear axle load incl. load transfer and aero share), motor torque/speed
limits and the power limit, minus drag and rolling resistance; backward pass for braking.
Must run in < 50 ms for a 1 km lap (numpy, vectorised where possible).

### 5.3 Engine (`engine.py`, `vehicle_model.py`, `aero_model.py`, `powertrain_model.py`, `sensors.py`, `faults.py`)
Fixed physics step 0.01 s. The virtual car follows the lap-sim speed profile with a simple
"driver" model (small lap-to-lap variation, seed-controlled), and every step computes the true
state of every subsystem, then each **virtual sensor** samples at its catalogue `rate_hz`,
applying first-order `lag_s`, Gaussian `noise`, `resolution` quantisation and range clipping.
The engine must produce **every raw channel in the catalogue** plus the truth channels.

* Wind: constant wind (speed, direction from config) + gusts → airspeed ≠ ground speed,
  flow yaw, pitot q uses airspeed.
* Aero model: per-element CL·A depends on ride height (front wing and undertray: ground
  effect — more suction when lower, sharp loss below a stall height ≈ 10 mm front / 12 mm
  floor), pitch, and flow yaw (outboard taps first). Tap Cp distributions are smooth, physically
  shaped (suction peak near the leading edge then pressure recovery; pressure side positive;
  undertray throat minimum ≈ fraction 0.4, diffuser recovery), and **calibrated so that
  `physics.section_cl` of the simulated taps reproduces the element's model section Cl within
  10 %**. Ride heights come from suspension compression under aero load and load transfer.
* Suspension: wheel loads = static + longitudinal & lateral load transfer + aero split + small
  road noise; pushrod = `physics.pushrod_from_wheel_load(...)`; damper = wheel travel ×
  damper motion ratio.
* Powertrain: motor torque from the driver demand (APPS) limited by torque/speed/power limits
  and derating; inverter DC power = mech power / (η_motor · η_inv); pack current from DC
  power and pack voltage; 140 `CellModel`s with per-cell manufacturing variation (capacity
  ±1.5 %, R0 ±5 %, seed-controlled); cell thermal model (I²R heating, air cooling that
  increases with car speed); temperature sensors read the mean of their nearby cells;
  motor winding & IGBT thermal RC models cooled by the coolant loop; radiator heat rejection
  ∝ (T_coolant − T_amb) × (UA₀ + UA₁·airspeed) — so aero and powertrain are coupled.
  Regen braking up to `regen_max_kw` when braking. BMS SoC reported by `bms_soc` (BMS's own
  estimate — make it Coulomb-counting based, low resolution 0.5 %).
* Safety chain: SDC = AMS ok ∧ IMD ok ∧ BSPD ok ∧ (no APPS implausibility latch). If the SDC
  opens: AIRs open, TS deactivates (`tsal_state` 0 after 1 s), motor torque 0, car coasts and
  brakes to a stop; it restarts (precharge → ready → driving) when the fault is cleared.
  APPS implausibility: |apps1 − apps2| > 10 percentage points for > 100 ms → torque cut.

### 5.4 Calibration targets (the sim must hit these; test them)
* `fs_endurance` lap time 55–80 s at the full 80 kW limit; v_max 95–120 km/h; peak lateral
  1.5–2.1 g; peak braking 1.3–1.9 g.
* Downforce at 25 m/s ≈ ½·ρ·v²·CL·A ≈ 1350 N (±15 %); aero balance 40–50 % front.
* Cp ranges: front wing suction peak −2.5…−4.0, rear wing −2.0…−3.5, undertray throat
  −1.5…−3.0; pressure side +0.2…+1.0.
* A full 22 km endurance at the 80 kW limit uses **95–110 % of usable energy** (so the
  endurance strategy feature matters: the predictor should recommend a lower power limit).
* Normal endurance: cell temps end at 40–52 °C (start 25 °C), motor winding 70–105 °C.
* Headless performance: ≥ 10× real time on one CPU core (`--speed max`).

### 5.5 Faults (`faults.py`, injectable in sim)
| id | system | effect | expected alert id(s) (§6.5) |
|---|---|---|---|
| `fw_damage_left` | aero | left front-wing flap damaged: L station suction −55 %, front CL·A −25 % | `aero_fw_asymmetry`, `aero_balance_shift` |
| `rw_stall` | aero | rear wing flap stall: aft suction taps collapse, rear CL·A −40 %, CD·A −10 % | `aero_rw_suction_loss`, `aero_balance_shift` |

| `cell_hot` | powertrain | cell 47 R0 × 4 (bad weld) | `bms_cell_temp_outlier`, then `bms_cell_overtemp` |

## 6. Analysis (`aerovolt/analysis/`)

`processor.py` — `Processor(ctx, store)`: `tick(t)` called by the session at `process_hz`
(default 20 Hz, driven by data time): reads `store.latest_all()`, computes every `calc_*`
channel (§2.2), writes them back with `store.update(t, calc)`, feeds lap detection, the SoC
estimators, energy integration, the alert engine and anomaly detection, then returns a list of
events (`alert`, `lap`, `strategy`). All analysis must work on **real data** (no access to sim
truth channels except for display), and must tolerate missing channels (NaN in → NaN out, no
exceptions).

* `aero.py` — ρ (moist air), q from `pitot_dp` (fallback ½ρv² from GPS speed when pitot is
  missing — flag `q_source`), airspeed, Cp per tap only when q > 60 Pa (else NaN), section Cl
  via `physics.section_cl`, wheel loads from pushrods, downforce total/front/rear removing
  static weight, vertical inertia (`az`) and longitudinal load transfer
  (`ΔF = m·ax·h_cg / L`), balance, CL·A = downforce / q (low-pass filtered, only when
  q > 120 Pa), drag from the longitudinal force balance (only when brakes released and
  torque ≥ 0): `F_drive = T·G·η / r`, `drag = F_drive − m·ax − C_rr·(m g + downforce)`,
  CD·A = drag / q, L/D, front-wing L/R asymmetry. Also offers `fit_cla(q, downforce)` (least
  squares through the origin) for the "downforce vs q" aero-map plot.
* `soc.py` — `CoulombCounter` and `SocEkf` (states: SoC, V_RC; measurement: mean cell
  voltage; model: `physics.CellModel` nominal params; tuned Q/R; documented maths).
* `powertrain.py` — pack/mech power, inverter efficiency (only when motoring above 5 kW),
  cell min/max/delta/idx, temperature stats, energy used / regen (kWh, integrated from pack
  power), cooling heat rejection `ṁ·cp·ΔT`.
* `laps.py` — lap detection by crossing the start/finish line (GPS → track frame, line from
  `ctx.track`; or a configured gate for real cars), with 5 s debounce; `LapSummary`: lap,
  lap_time, distance, v_avg, v_max, energy_kwh, regen_kwh, cla_avg, cda_avg, balance_avg,
  cell_t_max, cell_v_min, mot_temp_max.
* `strategy.py` — endurance energy strategy, run once per completed lap: laps needed =
  ceil(endurance distance / lap length), energy remaining from SoC (EKF) × usable energy,
  measured energy/lap → `calc_laps_remaining`; uses `sim/lapsim.solve` with the nominal
  vehicle model to compute energy/lap vs power limit (e.g. 40…80 kW in 5 kW steps), scaled by
  the ratio measured/predicted energy of the laps so far, and recommends the highest power
  limit that finishes with the reserve → `calc_power_limit_rec` + a `strategy` event
  `{laps_done, laps_needed, energy_remaining_kwh, energy_per_lap_kwh, recommended_kw,
  predicted_finish_soc, curve:[{kw, lap_time, energy_kwh}]}`.
* `anomaly.py` — per-tap learned baseline of Cp (EWMA mean & variance, learned only when
  q > 150 Pa and no aero alert active, warm-up ≥ 20 s of valid data). Deviation score per tap.
  **Classification:** one isolated tap deviating while its neighbours (same station/element)
  are normal → *sensor fault* (`sensor_tap_anomaly`); a cluster of ≥ 2 neighbouring taps
  deviating in a consistent direction → *aero change* (feeds the aero alerts).
* `alerts.py` — rule engine driven by `config/alerts.yaml`. Rule types: `threshold`
  (channel op value for `for_s`, hysteresis), `plausibility` (|a − b| > max_diff while
  b > min_value for `for_s`), `custom` (named Python check function registered in
  `alerts.py`, gets the processor state). Severity `info|warn|critical`. Emits alert events
  on raise and on clear.

### 6.5 Alert ids (must exist in `config/alerts.yaml`)
`aero_fw_asymmetry`, `aero_balance_shift`, `aero_rw_suction_loss`, `aero_ut_stall`,
`aero_high_yaw`, `sensor_pitot_implausible`, `sensor_tap_anomaly`, `sensor_stale`
(a raw channel that was live went stale while the source is running), `bms_cell_temp_outlier`,
`bms_cell_overtemp`, `bms_cell_voltage_outlier`, `bms_cell_undervoltage`, `bms_soc_divergence`,
`cooling_no_flow`, `motor_temp_high`, `inverter_temp_high`, `safety_imd_trip`,
`safety_sdc_open`, `safety_apps_implausible`, `energy_short` (strategy says the car will not
finish at the current power limit).

## 7. Real-sensor sources (`aerovolt/sources/`)

### 7.1 Serial line protocol (`protocol.py`) — what the sensor-node firmware prints
```
$AV,<node>,<ms>,<ch>=<value>[,<ch>=<value>...]*<CS>\r\n     data
$AVH,<node>,<fw_version>,<ch>[,<ch>...]*<CS>\r\n              hello (at boot and every 5 s)
$AVS,<node>,<ms>,<status>,<message>*<CS>\r\n                  status (ok|warn|error)
```
`<CS>` = two upper-case hex digits, XOR of every byte between `$` and `*` (NMEA style).
`<value>` is a decimal float (`nan` allowed). Lines with a bad checksum are counted
(`stats.checksum_errors`) and dropped. For beginners the parser also accepts a JSON object per
line: `{"fw_p03": -412.5, "amb_temp": 18.4}` (no checksum). `protocol.py` offers
`parse_line(line) -> ParsedLine | None` and `format_data(node, ms, values) -> str` (used by the
fake node and by tests).

### 7.2 `SerialSource` (`serial_source.py`)
Config: `{type: serial, port: /dev/ttyACM0 | COM5 | auto, baud: 115200, channels: [..optional..],
label: "Bench node"}`. Reads in a thread or via non-blocking reads, reconnects automatically
every 2 s if the port disappears (`status: waiting`), timestamps samples on arrival.

### 7.3 CAN (`canmap.py`, `can_source.py`)
* Bus: classic CAN, 11-bit IDs, 1 Mbit/s default, Intel (little-endian) byte order.
* **Signal name == channel id.** Layout in `config/can_layout.yaml`; `tools/gen_can.py` writes
  `can/aerovolt.dbc` and `firmware/sensor_node/include/aerovolt_can.h`; `--check` exits non-zero
  if the generated files are out of date (tested).
* "Signal not available" (SNA): raw value `0x8000…` (most negative) for signed signals,
  all-ones for unsigned. Decoders drop SNA values (channel not updated). Senders that do not
  own every signal in a message fill the others with SNA.
* Message map (IDs hex; `i16` = signed 16-bit, `u16` unsigned, scale per bit):

| ID | name | signals (in order, 16 bit unless noted) |
|---|---|---|
| 0x300–0x302 | AERO_FW_TAPS_A/B/C | fw_p01–04 / 05–08 / 09–12, i16 0.1 Pa |
| 0x303–0x305 | AERO_RW_TAPS_A/B/C | rw_p01–04 / 05–08 / 09–12, i16 0.1 Pa |
| 0x306–0x307 | AERO_UT_TAPS_A/B | ut_p01–04 / 05–08, i16 0.1 Pa |
| 0x310 | AERO_AIR | pitot_dp i16 0.1 Pa; amb_temp i16 0.01 °C; amb_press u16 1 Pa offset 50000; amb_rh u8 0.5 % |
| 0x311 | AERO_PROBE | probe_yaw i16 0.01; probe_pitch i16 0.01; rh_front u16 0.01 mm; rh_rear u16 0.01 mm |
| 0x312 | AERO_WING_LOADS | fw_load i16 1 N; rw_load i16 1 N |
| 0x320 | SUSP_DAMPERS | damper_fl/fr/rl/rr i16 0.01 mm |
| 0x321 | SUSP_PUSHRODS | pushrod_fl/fr/rl/rr i16 1 N |
| 0x330 | IMU_ACCEL | ax, ay, az i16 0.002 m/s² |
| 0x331 | IMU_GYRO | gx, gy, gz i16 0.01 deg/s |
| 0x340 | GPS_POS | gps_lat i32 1e-7 deg; gps_lon i32 1e-7 deg |

| 0x400 | INV_STATUS | mot_speed i16 1 rpm; mot_torque i16 0.1 Nm; inv_dc_voltage u16 0.1 V; inv_dc_current i16 0.1 A |

* `CanSource` config: `{type: can, interface: socketcan|virtual|slcan|pcan|kvaser, channel:
  can0, bitrate: 1000000, dbc: can/aerovolt.dbc, channels: [...optional]}`. Uses python-can

## 8. Data logging (`aerovolt/datalog/`)
Wide CSV (gzip optional `.csv.gz`), one row per store snapshot (20 Hz): header
`t,<channel ids...>`; a second header line starting with `#units,`; NaN written as empty.
Metadata JSON sidecar `<log>.meta.json` (config, vehicle name, start time, faults timeline,
alerts, laps). `reader.py` loads it back (numpy). `tools/export_wide.py` resamples/filters.

## 9. Server (`aerovolt/server/`)

`session.py` — `Session(config)`: builds context, catalogue, sources, `SourceManager`,
`ChannelStore`, `Processor`, logger. Drives processing at `process_hz` of **data time**
(so accelerated sims process correctly) plus a 1 Hz wall-clock fallback for real sources (to
detect staleness when no data arrives). Keeps alerts, laps, faults timeline. Also runs headless.

`app.py` — aiohttp application:
* `GET /` and static files from `web/`.
* `GET /ws` — WebSocket. On connect the server sends **hello**, then **frame** messages at
  `broadcast_hz` (default 20 Hz, wall clock) and events as they happen.
* REST: `GET /api/hello` (same as hello), `GET /api/history?ids=a,b&seconds=60` →
  `{t:[...], series:{a:[...], b:[...]}}`, `GET /api/faults`, `POST /api/faults/{id}` body
  `{"active": true}` → 200 with the fault list (409 if the source has no sim), `GET /api/laps`,
  `GET /api/alerts`, `POST /api/session/reset`, `GET /api/sources`.

WebSocket messages (JSON, server → client):
```json
{"type":"hello","version":"1.0","mode":"SIM","session":{"name":"...","started":"ISO-8601"},
 "sources":[{"kind":"sim","label":"Simulator","status":"running","detail":"fs_endurance ×1.0","stats":{}}],
 "channels":[ChannelDef dicts], "track":{Track.to_json}, "vehicle":{vehicle.yaml as dict},
 "faults":[{"id":"cell_hot","title":"...","system":"powertrain","description":"...","active":false}],
 "alerts":[active alerts], "laps":[LapSummary...], "strategy":{...}|null, "t":12.34}
{"type":"frame","t":12.40,"v":{"fw_p01":-523.1,"cell_v_000":3.912, "...":null},
 "owner":{"fw_p03":"serial"}}         // owner only lists channels not owned by the default source
{"type":"alert","alert":{"id":"bms_cell_overtemp","rule":"bms_cell_overtemp","severity":"critical",
 "title":"Cell over-temperature","detail":"cell 47 at 61.2 °C","channels":["cell_t_20"],
 "t_start":512.3,"t_end":null,"active":true}}
{"type":"lap","lap":{LapSummary}}
{"type":"faults","faults":[...]}
{"type":"strategy","strategy":{...}}
{"type":"sources","sources":[...]}      // every 1 s
```
Frame values: rounded sensibly (≈ 4 significant figures beyond resolution), NaN → null.

CLI (`__main__.py`):
```
python -m aerovolt [--config config/demo.yaml] [--host 127.0.0.1] [--port 8080] [--speed 1.0|max]
                   [--track fs_endurance] [--fault ID@T ...] [--log PATH] [--open]
                   [--headless --duration SECONDS]   # no server; prints laps/alerts summary
```

## 10. Web dashboard (`web/`)

No build step. ES modules + import map (`three` → `./vendor/three/three.module.js`,
`three/addons/` → `./vendor/three/addons/`). Works offline (no CDN). Dark "pit-wall" theme,
tabular numerals, 1366×768 minimum, scales to 4K.

`js/app.js` exports the singleton `app`:
```js
app.meta            // hello payload
app.channels        // Map id -> ChannelDef
app.latest          // Map id -> number|null
app.owner           // Map id -> 'sim'|'serial'|'can'|'replay'
app.t               // latest session time

app.alerts          // Map id -> alert (active ones), app.alertLog: [] (all)

app.on(evt, cb)     // 'hello'|'frame'|'alert'|'lap'|'faults'|'strategy'|'sources'|'connection'
app.api.get(path), app.api.post(path, body)
app.fmt(id, value = app.latest.get(id)) -> string with unit and precision from resolution

app.val(id) -> number (NaN when missing)
```
Panels are ES modules with `export function mount(rootEl, app)` and
`export function update(app, dtMs)` (called from one `requestAnimationFrame` loop, only for the
visible tab; throttle heavy work). Tabs: **Overview** (`overview.js`), **Aero** (`aero.js` +
`car3d.js`), **Powertrain** (`powertrain.js`), **Sensors** (`sensors.js`), **Laps** (`laps.js`).
Global: header (mode badge SIM/LIVE/HYBRID/REPLAY, connection, lap, lap time, speed, SoC),

`js/lib/charts.js` provides `StripChart`, `XYChart`, `Gauge`, `BarChart`, `Sparkline`;
`js/lib/colormap.js` provides `diverging(v, vmin, vmax)` (Cp: blue = suction, red = pressure)
and `sequential(v, vmin, vmax)`; `js/lib/format.js` number/units helpers.

## 11. Firmware (`firmware/sensor_node/`)
PlatformIO project, environments `teensy41` (FlexCAN_T4), `esp32dev` (TWAI driver),
`nano_serial` (serial output only). Reads Sensirion SDP3x/SDP8xx differential pressure sensors
(I²C, CRC-8 poly 0x31 init 0xFF, continuous mode, behind a TCA9548A I²C mux when several share
an address), a BME280 (ambient), analog linear potentiometers (dampers) and HX711 load cells.
Outputs CAN frames per `aerovolt_can.h` **and/or** `$AV` serial lines (§7.1). The bit-packing,
checksum, CRC and conversion code lives in `lib/avcore/` (no Arduino dependency) and is unit
tested on the host with g++ (`make -C firmware/sensor_node/test/host test`). A Python test
compiles a small host program that packs test vectors and compares the bytes with cantools'
encoding of the same values from `can/aerovolt.dbc` — firmware, DBC and Python must agree
bit-for-bit.
